# UDP VPN

客户端支持 `udp://主机:端口/vpn`。服务端增加 `vpn-udp-listen`，独立于 QUIC UDP 的 `vpn-listen` 和代理的 `quic-listen`；三者不能使用相同的 UDP 端口。TCP 监听可使用相同数字端口。

```ini
# Server: keep the existing QUIC/TCP listeners, add a separate UDP listener.
vpn-udp-listen = 0.0.0.0:8445

# Client: choose this endpoint in the same VPN configuration form.
vpn-server = udp://vpn.example.com:8445/vpn
```

两端更新二进制及管理页面。放行服务器防火墙和云安全组的 UDP 8445；服务端保存后点击“重启 VPN 使配置生效”。客户端可先用“测试 VPN 连接”，再保存地址：已启动的 VPN 自动切换，已停止的 VPN 保持停止。原有虚拟地址自动分配、路由清理、Windows 控制 APP、白噪音和在线参数调整均复用。

如果只启用 UDP VPN 入口，可设置 `vpn-listen = ''`、`vpn-tcp-listen = ''`。该 VPN 入口不要求证书或 CA；仍使用两端相同的 32 字节共享密钥 `vpn-key-file`，留空复用 `key-file`。其他仍启用的 QUIC/TLS 入口继续校验证书。不要把 UDP 模式理解为明文转发。

独立 CLI 对应 `udp-listen` 和 `server`：

```sh
sgate-vpn -role server -listen '' -udp-listen 0.0.0.0:8445 -key-file /path/to/sgate.key
sgate-vpn -role client -server udp://vpn.example.com:8445/vpn -key-file /path/to/sgate.key
```

需要 Go 1.24 或更新版本编译；使用包含安全修复的 Pion DTLS v3.1.15。

## 传输与安全

原有 QUIC VPN 的 IP 数据使用不可靠 QUIC DATAGRAM，不对 IP 数据做 QUIC 重传；其拥塞控制仍可能限制吞吐。UDP 模式通过原生 UDP 数据报承载 DTLS 1.2 加密记录，不使用 TCP、WebSocket、QUIC 拥塞控制或可靠流。数据报之间不存在隧道层的按序交付要求。

使用 DTLS-PSK、AES-128-GCM、扩展主密钥和独立协议标识；从现有共享密钥派生本协议的 PSK。DTLS 提供随机会话密钥、序列号、完整性校验和 4096 个记录的滑动防重放窗口。会话不复用缓存；每次连接重新握手。认证后继续校验应用层共享密钥证明、子网和 MTU，并原子分配虚拟 IP。未认证连接不会占用虚拟地址。

每个业务数据片段只写入一次，不发送 ACK/NACK，不保存重传副本，不做 FEC，也不跨断线重放。丢失、篡改、重复或接收队列满时丢弃。内层 TCP 自行恢复丢失的数据；内层 UDP 保持不可靠语义。大 IP 包仍使用已有的有界分片重组机制；分片丢失只导致该 IP 包无法交付，不请求补片。

认证握手超时为 8 秒，DTLS 握手重发间隔设为 30 秒，因此单次建连不会因定时器再次发送握手 flight；控制数据也不增加可靠传输。连接测试的 UDP 回显只尝试一次，丢失时显示失败。连接失败或会话超时后，客户端仍按现有退避策略建立新会话；这是恢复连接，不是重传业务包。

两端每 15 秒各发送一个单向保活包，无需回复；60 秒没有收到数据报时结束会话并清理或重连。NAT 出口或端口发生变化时需要重建会话。关闭通知尽力发送一次，不等待 ACK；丢失时由空闲超时释放服务端租约。

## 应用包头

以下包头及载荷整体处于 DTLS 加密记录内。未知版本、类型、非零保留字段或长度不匹配均丢弃。

| 字段 | 字节数 | 含义 |
|---|---:|---|
| 标识 | 3 | `SGU` |
| 版本 | 1 | 当前为 `1` |
| 类型 | 1 | `1` 控制、`2` 数据报、`3` 保活、`4` 关闭、`5` 控制通道结束 |
| 保留 | 1 | 当前必须为 `0` |
| 载荷长度 | 2 | 网络字节序；不包括包头 |

单个应用帧最多 1200 字节。业务片段负载沿用 1000 字节上限，避免外层 IP 分片；TCP MSS 调整、64 包发送调度队列与 64 包接收队列继续生效。完整 IP 包不因数据报乱序而等待其他连接的包。

## 指标与验证

概览显示实际 `UDP` 协议、独立监听地址、客户端公网 IP / VPN IP，以及 UDP 数据报发送、接收、接收队列丢弃累计数。数据报计数包括业务片段、白噪音及连接测试回显，不包括安全握手和其他控制包；不是线速字节数，也不能直接当作丢包率。UDP 模式不显示 QUIC 拥塞窗口或 QUIC RTT。

本机测试覆盖实际加密 UDP 双向 IP 传输、自动分配、多客户端、重连、白噪音、丢包后不补发、后续数据无按序等待、乱序、重复密文防重放、密文篡改拒绝、错误密钥拒绝、设置与前端校验。另使用用户态网络栈验证内层 TCP 的大资源下载和上传。Windows/Linux 使用交叉构建；Windows 驱动仍未实机验证。

没有真实中美弱网实测，不能据此承诺比 QUIC 或 TCP/WSS 更快。UDP 没有外层拥塞控制；拥塞、限速或 UDP 丢包严重时，内层 TCP 仍会降速，应用 UDP 也可能损失更多数据。请在相同带宽、RTT、丢包条件下对比吞吐和加载时延。
