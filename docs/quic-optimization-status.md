## 本机结果与边界

新增资源/QUIC 专项、健康 API、监听恢复有竞态测试；前端测试共 78 项，77 通过、1 跳过。完整项目竞态测试中隧道包通过（约 540 秒）；应用包首次暴露监听关闭后等待超时的问题，修复后应用与管理包完整竞态回归通过，最终 QUIC/资源专项再重复 2 次通过，监听恢复与准入专项重复 3 次通过。其余项目包和两个服务框架依赖的竞态测试通过，`go vet`、客户端/服务端构建、Linux amd64 测试二进制交叉编译通过。完整项目测试与修复后专项/受影响包回归分别执行，没有将首次失败记录写成一次性全绿。QUIC 在默认 1200 字节初始 UDP 负载下，1250 字节负载限制测试会实际丢弃 PMTU 探测包并验证有效负载完整性。NAT 测试替换中继的上游 UDP 源端口，验证已有业务 TCP 连接继续使用同一个后端套接字；不代表所有真实 NAT 设备行为。

## 主要使用说明

- 原生模式默认开启；连接旧服务端需显式 `quic-mode = "legacy"`，不自动降级。
- `memory-budget-bytes` 默认 0，不限制；例如配置 `"256M"` 显式启用。它限制受管缓冲容量预留，不限制整体 RSS。
- 修改 QUIC 窗口、初始包大小、QUIC 启用时的最大流数和进程总预算，需重启整个进程；管理界面会拒绝仅替换代理的操作。
- 已认证的 `/admin/api/health` 返回 200/503，统计 API 提供 `memory` 与 `health`；UDP 监听退出不再只记日志。
- Linux 内核整形尚未运行验证。脚本在私有命名空间执行，有前置条件检查、身份校验和清理，实际内核/工具兼容性需在后续 Linux 环境确认。
